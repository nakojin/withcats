# 모션 가이드

모션은 **원인과 결과를 보여 줄 때만** 쓴다. 장식만을 위한 움직임은 표현형 레이어에서 화면당 하나로 제한.

## 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--t-fast` | 120ms | 눌림, 호버, 토글 |
| `--t-med` | 220ms | 칩·탭 전환, 토스트 등장 |
| `--t-slow` | 400ms | 시트·페이지 전환 |
| `--ease-out` | `cubic-bezier(.2,.8,.2,1)` | **들어오는** 것 (기본값) |
| `--ease-in-out` | `cubic-bezier(.65,0,.35,1)` | 자리 이동 |
| `--ease-spring` | `cubic-bezier(.34,1.56,.64,1)` | 보상·획득 같은 "통통" 튀는 순간 |

`prefers-reduced-motion: reduce` 이면 세 지속시간이 0 이 된다. 직접 쓴 `@keyframes` 도 반드시 `var(--t-*)` 를 쓰거나 같은 미디어쿼리로 끈다.

## 원칙

1. **나갈 때는 들어올 때보다 빠르게** — 등장 220ms, 퇴장 150ms 정도.
2. **`transform` 과 `opacity` 만 애니메이션** — `width`/`top`/`box-shadow` 는 레이아웃·페인트를 다시 해서 버벅인다.
3. **거리는 짧게** — 슬라이드는 8~24px 이면 충분. 화면 전체를 가로지르는 건 시트·페이지뿐.
4. **동시에 여러 개면 30~50ms 간격으로 순차**(stagger). 10개 넘으면 처음 몇 개만.
5. **누름 피드백은 즉시** — `:active { transform: scale(.97) }` 는 지연 없이.
6. 300ms 넘는 대기에는 스피너 대신 스켈레톤 또는 진행률.

## 상황별 처방

| 상황 | 처방 | 도구 |
|---|---|---|
| 버튼 눌림 | scale .97, `--t-fast` | CSS |
| 바텀시트 | 아래에서 올라옴 + 배경 페이드, `--t-slow` `--ease-out` | `.kit-sheet` (CSS) |
| 토스트 | 아래 12px 에서 페이드 인, 2.4초 후 퇴장 | `toast()` |
| 리스트 추가·삭제 | 자동 레이아웃 애니메이션 | AutoAnimate (#48) |
| 숫자 변화 (XP·가격) | 자릿수가 굴러가는 전환 | NumberFlow (#52) |
| 페이지 전환 | View Transitions API 우선, 미지원 시 그냥 이동 | CSS `@view-transition`, swup (#53) |
| 스크롤 연출 | `animation-timeline: view()` 우선, 복잡하면 GSAP ScrollTrigger | CSS / GSAP (#45) |
| 보상·레벨업 | `--ease-spring` + 짧은 파티클, 1초 이내 | canvas-confetti 등 |
| 타이틀 등장 (표현형) | 스큐된 붓칠이 먼저, 글자가 0.1초 뒤 | `expressive.css` + GSAP |

## 하지 말 것

- 스크롤을 가로채는 효과(스크롤 잭킹).
- 자동으로 계속 도는 캐러셀 — 하려면 정지 버튼 + 호버/포커스 시 멈춤.
- 로딩 화면을 일부러 길게 보여 주는 연출.
- 1초에 3번 넘는 깜빡임 (광과민성 발작 위험, WCAG 2.3.1).
